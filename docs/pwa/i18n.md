# Internationalisation (i18n)

Ce document décrit le système de traduction de la PWA. La configuration est volontairement plus simple que celle de l'admin web : pas de SSR, pas de multi-namespace, pas de synchronisation avec l'URL.

---

## Différences avec l'admin web

| Aspect | Admin web | PWA |
|---|---|---|
| Initialisation | `await i18n.init()` avant hydratation | Init synchrone au démarrage du module |
| Namespaces | `common`, `auth`, `validation`, `navigation` | Namespace unique (`translation`) |
| SSR | Instance par requête côté serveur | Non applicable |
| Langue dans l'URL | `/:lang/...` + `useLanguageSync` | Pas de préfixe URL |
| Changement de langue | Via l'URL (navigation) | Via `i18n.changeLanguage()` (profil) |

---

## Configuration (`src/services/i18n.ts`)

```ts
i18n
  .use(Backend)
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    fallbackLng: "en",
    supportedLngs: ["en", "fr"],
    interpolation: { escapeValue: false },
  });
```

| Clé | Valeur | Description |
|---|---|---|
| `fallbackLng` | `"en"` | Langue utilisée si la locale détectée n'est pas supportée |
| `supportedLngs` | `["en", "fr"]` | Langues acceptées |
| `interpolation.escapeValue` | `false` | Désactivé car React échappe déjà les valeurs |

Aucun `defaultNS` ni tableau `ns` n'est configuré - i18next utilise le namespace par défaut `"translation"`.

Le fichier est importé directement dans `main.tsx` (ou équivalent). L'initialisation se produit à l'import du module, de façon synchrone - il n'y a pas d'`await` avant le rendu React.

---

## Fichiers de traduction

Le backend `i18next-http-backend` utilise son chemin par défaut en l'absence de configuration explicite :

```
/locales/{{lng}}/{{ns}}.json
```

Comme un seul namespace est utilisé, les fichiers effectifs sont :

```
public/
└── locales/
    ├── fr/
    │   └── translation.json
    └── en/
        └── translation.json
```

---

## Détection de la langue

`i18next-browser-languagedetector` est utilisé sans configuration personnalisée. L'ordre de détection par défaut est :

```
querystring -> cookie -> localStorage -> sessionStorage -> navigator -> htmlTag -> path -> subdomain
```

En pratique, la langue est lue depuis `localStorage` (si une préférence a été sauvegardée via `changeLanguage`) ou depuis les préférences du navigateur (`navigator`).

## Utilisation dans les composants

Pas de namespace à spécifier - `useTranslation()` sans argument :

```ts
const { t } = useTranslation();

t("login.title");
t("error.lengthConstraint", { min: 2, max: 100 });  // interpolation
t("register.success");
```

## Changement de langue

La langue se change via le sélecteur dans la page Profil :

```ts
const { i18n } = useTranslation();
i18n.changeLanguage("fr");
```

`i18next-browser-languagedetector` persiste automatiquement le choix dans `localStorage`. La préférence est restaurée à la prochaine ouverture de l'application.

La langue courante est récupérée et tronquée au code de base dans les composants qui en ont besoin :

```ts
const currentLang = i18n.language?.split("-")[0] || "fr";
```

Ce pattern est nécessaire car `i18n.language` peut retourner `"fr-FR"` (format complet) ou `"fr"` (code court) selon la source de détection.
